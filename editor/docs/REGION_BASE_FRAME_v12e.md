# 区域画布基帧口径修复（v12e）

日期：2026-10-08。范围：编辑台 app（~/vtouch-editor）—— 仓库/核心/面板/契约**零改动**。
触发：用户报障「横屏下区域渲染在画布中的位置不对，而且一进来看不见所有区域，可能是受帧的大小影响」。

## 一、根因（盘上代码对账）

**区域数字口径 = 「基帧视口坐标」（viewport-carry），不是固定竖屏逻辑：**

- 面板 `src-ui/vtouch_ui.cpp:459-493`（region_rot_map）+ `:396-417`（p2c_rot/c2p_rot）：
  存储值属于 regions.conf `#frame` 记录的「基帧」；转屏时按「以当前方向左上角为原点的 xy 原样保留」
  重算写回（2026-10-03 用户口径）。**批不变量：显示/命中位置 = p2c_rot(基帧, 数值)，与当前帧方向无关。**
- 核心日志实测（22:10 用户会话，/data/local/tmp/vt_ui_core.log）：
  `region upd r1 … 2325,686 → 655,2325 …`（转横屏批次）→ 回退 `2325,686`（转回竖屏）✓ 与上式互证。
- 数值可越出竖屏逻辑（0..1440/0..3168）之外——面板/核心均允许（「屏外允许，屏幕自己裁」）。
  现有 live 数据：`#frame 0 1440 3168` + r1(2325,686)/s1(2234,1265)/c1(2780,320) = 横屏时期画、
  按基帧 0 解释的「原始视口数字」；c2(720,1452) 为竖屏时期画。
- **app 侧（修复前）**：把存储值当「竖屏逻辑」，按**当前帧 rot** 投影
  （`Matcher.logicRectToFrame(frameRot,…)` / `frameToLogic(frameRot,…)`；#frame 只原样透传、未参与换算）。
  横屏帧（rot=1）上被二次旋转：r1 → (686,−886)、s1 → (1265,−795)、c1 → (320,−1341) 全部飞帧外（看不见）；
  c2 → (1452,719) 出现到画面里（运行时它在横屏下恰恰是屏外）。**可见集合与运行时正好相反** → 两条报障现象全中。

## 二、修复（全部在 ~/vtouch-editor，备份 app/src.bak-v12e）

口径：**区域↔帧的一切换算以 `#frame` 基帧为基准；当前帧的 rot/尺寸不参与区域投影。**

- `Regions.java`：File 增 `frameRot/frameW/frameH`（解析 #frame）；静态 `lastFrameRot/W/H` 同步；序列化原样。
- `VisualPage.java`：`baseRot()/baseW()/baseH()` 助手；统一换基帧——projectLogic/rebuildShapesFromFile、
  换帧折回(keep-fold)、MODE_REGION 预载/回填/读数、updateRegionsInfo 读数、saveAllRegionsSync
  （按**刚读的盘上文件**基帧回写，与写出的 #frame 行配对）、区域限定（模板/点集试查）矩形。
- `CaptureChip.java`：[框区域] 预览与保存按基帧（保存时在 bg 重读文件取基帧）；干跑改按基帧取区域矩形。
- `DryRun.java`：run() 增基帧参数；frameRegion 按基帧。
- **保留勿动**（native_cur 口径，供操作/模板坐标，不同于区域表）：取点/吸色/模板命中读数、
  屏幕取点回填 = `Matcher.frameToLogic(帧 rot)`。
