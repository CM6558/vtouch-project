# Repository guidance

- This is a device-side Android Java project, not a Gradle project. The active sources are `app/src/com/vtouch/editor/*.java`; `app/src.bak-*` are historical snapshots and are not compiled. `MainActivity` is the launcher; the manifest also registers overlay-related services.
- Build on Termux with Java 17: `PATH=/data/data/com.termux/files/usr/lib/jvm/java-17-openjdk/bin:$PATH bash build.sh`. Java 21's `javac` output triggered an internal error in the bundled D8. The script also requires Termux Python at `/data/data/com.termux/files/usr/bin/python3`, the three jars in `sdk/`, and the icon and fonts named in the script. Java is compiled with `--release 8`; D8 targets API 24.
- The build deletes and recreates the entire `build/` directory and overwrites `out/vtouch-editor.apk` and `out/vtouch-editor-unsigned.apk`. Preserve any needed files there before running it. It creates `keys/vtouch.jks` only if missing; retain the existing key to keep APK signing identity stable.
- Packaging deliberately uses `tools/axml_encode.py`, `tools/arsc_encode.py`, and `tools/pack_apk.py` instead of aapt2/zipalign. The APK contains only the explicitly listed resources and assets in `build.sh`; update the packaging step and resource encoder as needed when adding resources. The manifest icon is the numeric ID `@0x7f010000`.
- After building, run a focused host check with `java -cp build/classes com.vtouch.editor.VtToStepsCheck` (also `VtFromStepsCheck`, `VtMigrateCheck`, `OpsV8Check`). The build compiles but does not run them. Some optional real-artifact scans skip when external fixture directories are absent; Android UI and services still need device verification.
- `scripts/migrate_scheme_v13.py FILE` writes a `.new` migration result; `--apply FILE` changes the input after creating a timestamped backup. Inspect the report before applying it to real data.
