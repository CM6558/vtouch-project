# vtouch-project —— 物理触摸 × 虚拟触摸合成（用户态，只需 root）

`EVIOCGRAB` 抓走真触摸屏，再用 `uinput` 建一个**合并触摸屏**：物理手指与注入的虚拟手指
合成**同一条**触摸流交给系统，应用侧只看到一块普通触摸屏。虚拟手指由核心自带的操作体系驱动
（面板编辑操作 + 区域触发执行；su 脚本自包含启动）；核心自带一块原生 ImGui 面板（只读状态 + 输入面板）。

一个可执行、零依赖（除 Android 系统库）：**设备上只需要 `vtouchd_ui` 一个文件**。

```sh
sh scripts/ui-deploy.sh all      # 编面板 + 编核心（面板内嵌）→ 推 1 个文件 → 起 → 自检
```

设备侧等价的一行（**逻辑尺寸不用传**，核心自己问框架）：

```sh
su -c 'cd /data/local/tmp && nohup ./vtouchd_ui >/data/local/tmp/vt_ui_core.log 2>&1 </dev/null &'
```

## su 脚本入口（自包含单文件）

主机侧 `python scripts/pack_su.py` 把 `build/vtouchd_ui` base64 内嵌进模板 `scripts/vtouch.sh.in`
（三个占位符 `<<PAYLOAD_MD5>>` / `<<PAYLOAD_SIZE>>` / `<<PAYLOAD>>` 在 `scripts/vtouch.sh.in:17-18`，
载荷写在标记行 `__VTOUCH_PAYLOAD_BELOW__` 之下，`:111-112`），生成**设备侧自包含入口**
`build/vtouch.sh`（产物只写 LF，`scripts/pack_su.py:43`；打包器自带「载荷解回来逐字节等于源二进制」
自检，`:37-40`）。设备上只要放这一个文件：

```sh
adb push build/vtouch.sh /sdcard/vtouch.sh
su -c 'sh /sdcard/vtouch.sh start'      # 装 + 起（幂等：已在跑只报状态）
su -c 'sh /sdcard/vtouch.sh status'     # 核心/面板 pid + 端口 + md5 + 日志尾
su -c 'sh /sdcard/vtouch.sh stop'       # SIGTERM → 先停面板、再放 EVIOCGRAB；10s 不退才 SIGKILL
su -c 'sh /sdcard/vtouch.sh install'    # 只装不启
```

| 子命令 | 行为 |
|---|---|
| `install` | 解载荷 → 长度/md5 对账 → `chmod 755` → 原子 `mv` → **回读 md5**（`scripts/vtouch.sh.in:41-52`）；设备上已是同一 md5 就直接跳过（`:36-40`） |
| `start` | 先 `install`，再起核心并等日志出现 `engine=on`（最多 8s；`:55-75`） |
| `stop` | 没在跑就直说；跑着就 `SIGTERM`（核心自己先停面板、再放 grab），10s 没退 `SIGKILL`（`:77-90`） |
| `status` | 内嵌版本与设备已装两份 md5 对摆，核心/面板 pid + 端口 27183（`/proc/net/tcp` 找 `6a2f`）+ 日志尾 15 行（`:92-98`） |

「装完必回读」是这套入口的口径：安装链每一步都对账（长度 `:45`、md5 `:47`、回读 md5 `:50-51`），
`status` 又用 pidof / 端口 / md5 三样把「跑没跑、听没听、装的是不是这份」一次摆出来 ——
md5 不一致就是没装上或被换过。无参数 = 用法 + 退出 2（`:105`）；非 root = 提示 + 退出 1（`:24`）。

`scripts/vtouch.sh.in` 是**模板**（保留占位符，别直接推它）；`build/vtouch.sh` 是产物（不入库，换核心就
重跑打包器；同一输入两次打包逐字节一致）。旧 JS 客户端通道已全退役（2026-10-05，见 git 历史）。

## 操作编辑器（面板「操作」页）

面板侧栏「页面」组六页：区域列表 / **操作** / **方案** / 事件日志 / 设置 / 说明（`src-ui/vtouch_ui.cpp:2528-2534`）。
「操作」页把「点按 / 滑动 / 等待 / 按下 / 弹起 / 区域判断 / 开关判断 / 跳转 / 计算 / 找图 / 找色」十一种步骤编成一条操作
（上限 16 条、每条最多 32 步），点一下就能在屏幕上跑出来 ——
编辑与运行都在面板里完成，不依赖外部客户端。

**页面**：页头（左标题 + 右侧条数）+ 运行读数（`运行中：<名> · 第 k/n 步` / `空闲`）+ `＋新建`（新条默认
1 步「等待 100ms」）；每条一张卡片：`名字` + `N 步 · 门控 <r1|无> · 跑完自动关 <开|关>`，
按钮 `[运行]`（运行中变 `[停止]`）/ `[编辑]` / `[删除]`。

**编辑**（`[编辑]` 开整面覆盖层，`src-ui/vtouch_ui.cpp:3685`）：名字行（点开字符键盘；与区域 id 同规则
`[A-Za-z0-9_-]`、1..15，**裸 `-` 除外**）、步骤表（每行 `1. 点按` + 参数小字，带 `[参数][↑][↓][删]`）、
**加步键 3×3**（`[＋点按][＋滑动][＋等待]` / `[＋按下][＋弹起][＋跳转]` / `[＋区域判断][＋开关判断][＋计算]`；
窄屏省略「＋」；`src-ui/vtouch_ui.cpp:4941-4966`）、
`门控开关：<无|r1|…>`（点击循环）、`跑完自动关：开/关`、头排 `[预览] [收起]`、`[取消]/[完成]`。
坐标与毫秒走面板自绘数字键盘（无输入法）；**参数弹层 v3 = 该步全部数值字段一屏**（点格切换激活格；
`[变量]`（9 项中文名：触发变量 5 + 结果 1..4，+「数值」回退）仅激活的可变量格显示、`[取点]` 仅激活的坐标格显示；
`src-ui/vtouch_ui.cpp:3954-4204`）；**本地缓冲原子落** —— 进层快照、层内只改缓冲，`[完成]` 全字段
校验全过才一次写回，`[取消]` 全丢（`src-ui/vtouch_ui.cpp:4156-4200`）。条件步行内多一个区域下拉 +
**成立 / 不成立两枚四档循环钮**（继续下一步 → 跳过下一步 → 跳到… → 中止；档位 = 跳到… 时该侧出现
目标格，点它编 0..32、0 显示「结束」；开关判断的列表只列开关型；`src-ui/vtouch_ui.cpp:3809-3846`、`:3905-3917`）。

**布局（v2）**：横屏 = 左右分栏（左 ~60% 步骤列表主区、右 = 名字 / 门控·自动关 / 加步 3×4 / 预览 / 完成）；
竖屏 = 列表主区 + 加步区 4×3 紧凑置底；最短边 ≥640 全元素可达。

**整屏与收起**：编辑层（含各子层）按**当前屏整屏**绘制；头排 `[收起]` 收成底部一条（编辑状态全保留，
点条展开）；**取点自动收起** —— 点 `[取点]` 即收成底部条「点屏幕上目标位置 · 点这里取消」，回填 / 取消 /
20s 兜底超时都自动弹回（参数层保持；`src-ui/vtouch_ui.cpp:4071-4081`、`:5776-5781`）。吞触摸矩形三态随
状态切：编辑展开 = 整屏、收起 = 只吞底部条（其余整屏给游戏 / 取点落点）、关层 = 面板窗口（`src-ui/vtouch_ui.cpp:1550-1559`）。

**预览页**（`[预览]` 进入，页面本体 `src-ui/vtouch_ui.cpp:4773-4844`）：全屏只读 —— 步骤清单（每步一行摘要；条件步
两行分支 `├ 成立 → …` / `└ 不成立 → …`；跳转 `→ 第 N 步` / `→ 结束`；计算 `计算 → rN = <表达式>`）+ 坐标小地图（竖屏逻辑比例：
点按 = 蓝点 / 按下 = 橙点 / 判定点 = 紫叉 / 滑动 = 带箭头连线；每点旁标步号，越界贴边标注）。

**变量（触发数据）**：5 个运行内只读变量 —— `tdx / tdy / tux / tuy / tms`（界面名：触发按下x / 触发按下y /
触发弹起x / 触发弹起y / 触发时长）；字段里用**负数编码**：`-1=tdx  -2=tdy  -3=tux  -4=tuy  -5=tms`
（字面值恒 ≥0；v2：`-6/-7 = fx/fy` 视觉命中、`-10..-25` = 自定义变量，见下）。来源：**完整按压**触发 5 个全有值；**按下**触发
只有 `tdx/tdy`；面板手动运行全部无值。起跑瞬间快照、运行中不回填（同 v1 整条快照口径）；引用**无值**
变量 → 运行到该步中止（`op 中止 … 原因=变量无值`，不静默当 0）。`VTOUCH_OPS_TRACE=1` 时起跑多一行
`op 变量 tdx=… tdy=… tux=… tuy=… tms=…`（未设打 `-`）。

**计算（第 9 类步骤；v2 起变量可命名）**：`变量 = 表达式` —— 操作数 = 触发数据 / 自定义变量 / 找图找色命中坐标
（fx/fy）/ 数字字面量，运算符 `+ - * /` 与括号，函数 `atan2 sin cos abs min max sqrt`（三角函数按度，`atan2(0,0)=0`）；
长度 ≤63 字符、括号 ≤8 层、空白忽略。**自定义变量**（≤16 个，默认名 v1/v2… 可改）运行内有效、**起跑清零**、
不落盘；表达式与后续步骤都可引用。`[＋计算]` 加一步（默认 v1、空表达式）并立即打开**表达式子层**；
计算步的 `[参数]` 同入口。求值错（除零 / 域错 / 非有限）→ 中止 `原因=表达式错`；引用未写的变量 →
中止 `原因=结果无值`；变量值当坐标 / 时长 → 四舍五入取整 + 夹取到字段合法域（**不中止**）。按住期间
**允许**计算（纯计算不碰手指）。

**找图 / 找色（第 10/11 类步骤）**：找图 = 先存模板（「模板」页截帧框选/吸色点选存 `.tmpl`/`.pts`），步骤里选模板名
（可限定区域）；找色 = 填颜色（十六进制）+ 容差（0–255），多点找色还要选点集。命中 → 坐标写进 **fx/fy**（系统预置变量）
+ 走「成立」档；未命中 → 「不成立」档（四档语义同条件步）。**持续查找**：打开后设超时（毫秒，存 ms 列；0 = 单次），
一遍遍重新找、命中即停、超时走「不成立」。步骤参数层（与「模板」页）有 **[试一下]**：当场找一次，显示「命中 (x, y) /
未命中」并在屏上框出位置（约 2 秒）——抓帧用图层 skip-screenshot 免隐藏（帧里不会带上面板与区域，不闪烁；老 ROM 回退隐藏路径）。**截帧选择器**：缩放
`[＋]/[－]/[适应]`、拖画面平移、选择框四角/整体拖拽、`[确认]` 后可继续调整。

**字段直接写算式（v2）**：坐标 / 时长等字段的参数层加 `[数值]/[变量]/[表达式]` 三模式 —— `[表达式]` 直接写算式
（如 `按下x+100`），确定时自动在该步**前**插入一条 `计算 <自动名 e1…> = <表达式>` 并把字段指向该变量（跳转目标随插步位移）。
**自定义变量（v2）**：不再固定 r1..r4 —— 计算步命名存值（≤16 个）；预置变量 = 触发数据（tdx/tdy/tux/tuy/tms）+ 视觉结果
（fx/fy）；任何「允许变量」的字段都能在 `[变量]` 列表里引用。表达式里 v4 旧名 `r1..r4` 也兼容解析（r1/r2=fx/fy、r3/r4 恒未写）。

**按下 / 弹起**：按下 = 坐标字段（down 并保持），弹起 = 无字段（松开）；用起跑时挑定的那个虚拟槽。
按住期间只允许 等待 / 区域判断 / 开关判断 / 弹起（及跳转步 / 计算 —— 纯控制流），出现 点按 / 滑动 / 按下 →
中止（`原因=槽占用`）；
没按住就弹起 → 中止（`原因=未按下`）；正常完成 / 中止时若还按着 → 自动松开 + 日志 `op 收尾 松开`。

**条件步**：区域判断 = 检查点（字面 / 变量 / 取点）在不在 `ref` 区域内（停用区域 = 恒不命中；区域不存在 →
中止 `原因=区域不存在`）；开关判断 = `ref` 区域须开关型（否则中止 `原因=非开关型`），成立 = 开着。
**成立 / 不成立两侧各四档**（新步默认：成立 = 继续、不成立 = 中止）：**继续下一步 / 跳过下一步**（步序
+1，跳过紧随其后那一步、不执行也不求值；末步跳过 = 正常完成）/ **跳到第 N 步**（该侧目标 0..32，0 = 结束；
保存预检按当前步数收紧为 0..步数）/ **中止**（不成立侧原因 `条件不成立`、成立侧原因 `条件中止`）。
日志：不成立侧恒打、成立侧 ≠ 继续才打 ——
`op 条件 <区域判断|开关判断> <ref> <成立|不成立> → <继续下一步|跳过下一步|跳到第 N 步|跳到结束|中止>`。
编辑期只查 ref 的长度 / 字符集，存在性不校验、允许悬空。

**跳转步**：直接跳到指定步骤继续（目标 0..32）—— **0 = 结束** = 直接正常完成（收尾释放 / `跑完自动关`
照走），不占跳转计数、不判上限；1..步数：前跳 = 跳过中间步骤，后跳 = 循环（如跳回第 1 步重来）。
**跳转守卫**：条件跳转 + 跳转步共用一枚计数（起跑清零），单次运行跳转超过 **200 次** → 中止
`原因=跳转超限`（防死循环）。步级日志 `op 步 k/n 跳转 第 N 步` / `… 跳转 结束`，`VTOUCH_OPS_TRACE=1` 时
每跳一行 `op 跳转 <名> 第 A 步 → 第 B 步`（B=0 打 `→ 结束`）。

**运行**：`[运行]` 起跑 —— 执行器在**核心主线程**（面板崩了不打断已起跑的操作），一次只跑一条、
忙时新触发丢弃（日志 `op 丢弃 忙`）；运行中 `[停止]` 中止并抬指。步骤语义：点按 = 按下 → 按住 ms → 抬起；
滑动 = 起点按下 → 每 ~10ms 线性采样 → 终点抬起；等待 = 纯延时；每步的开始时刻 = 上一步结束时刻
（要间隔就插「等待」）。门控 / 跑完自动关见下方**触发侧**。

**触发侧**（区域列表 → 操作）：区域卡片三行（在四键上方；点击切换；`src-ui/vtouch_ui.cpp:2683-2699`）——
`触发：<无|操作名>`（绑哪个操作）、`时机：<按下|完整按压>`、`开关型：<关|开 · 当前开/关>`。
**按下** = down 命中区域那一刻触发；**完整按压** = down 命中先锁存，该手指抬起时触发一次（抬起位置不限）。
触发只由**物理手指**产生（虚拟触点不进队列 —— 不会自己触发自己）；绑定不存在的操作**允许悬空**
（触发时解析失败 = 丢弃 + 日志）。**开关型**：完整按压翻转开/关，核心推环行 `toggle_ev <id> <0|1>`
（面板记日志 + 立即重画）；面板绿样式 = `mark || (开关型 && toggle_on)`（脚本 `vt.mark` 兼容保留）；翻转与触发
各算各的（同一区域既当开关又绑触发互不影响）。**门控**：操作的 `门控` 非空 → 起跑前检查该区域必须
存在、是开关型且**开着**，否则丢弃（`op 丢弃 门控拦截`）；`跑完自动关 = 开` 的操作在**正常完成**时
把门控开关翻回关（中止不翻）。

**取点**：参数弹层里点 `[取点]` → 编辑层自动收成底部条「点屏幕上目标位置 · 点这里取消」→ 在屏幕上点
一下，核心**吞掉整段手势**并把**竖屏逻辑坐标一次填进激活格所在的坐标对（x 和 y 两格；滑动按当前激活的
一对 —— 起点对或终点对）**（与面板吞触摸同一处，`src/vt_frame.c:156-168`；回填日志 `取点 回填 第 N 步
参数 x,y = a,b`）。点收起条 = 取消；20s 超时兜底（核心惰性判 `src/vt_shm.c:211-223`、面板自带
`src-ui/vtouch_ui.cpp:5776-5781`），面板死了核心也会清（`src/vt_shm.c:243`）—— 不会留下「永远吞触摸」状态；
回填 / 取消 / 超时都自动弹回编辑层。取点成功另画**捕获标记**：捕获点 ~2 秒

## 逻辑尺寸：启动时自动获取

尺寸不是"屏幕多大"，是这套系统的**坐标契约**（区域表 / 区域事件 / 注入命令 / 脚本看到的
`device.width,height` 全都在同一个空间里），必须**固定、不随屏幕旋转变**。

| 情况 | 行为 |
|---|---|
| 传了 `-w 宽 -h 高` | 直接用，跳过探测（最高优先） |
| 没传，`wm size` 可用 | 取最后一个 `WxH`（有 `Override size:` 时它才生效）→ 归一化竖屏（短边当宽） |
| 没传，`wm` 不可用 | 打印原因并**退出**，要求显式 `-w/-h`（不静默用可疑来源） |

`wm size`（= AOSP 公开命令 `/system/bin/wm` → `cmd window size`）与脚本看到的尺寸**同源**。
启动时另有一条交叉校验：触摸屏 raw 量程比与逻辑尺寸比不一致会告警。

## 生命周期（谁拉起谁）

```
vtouchd_ui(root)
 └─ ① 取逻辑尺寸 → ② 建共享内存（单 memfd 三区）→ ③ 认触摸屏 → EVIOCGRAB → 建 uinput 合并设备
    → 监听 127.0.0.1:27183 → 起区域线程
    → ④ 自解包面板三件套 → fork/exec 面板（app_process … VTouchUI，共享内存 fd 传给子进程）
    → ⑤ 主循环（事件驱动）：读触摸 → 合帧注入 → 吃面板编辑邮箱 → 心跳/看门狗；
       空闲时睡在 poll 上（默认 1s 兜底），物理输入 / 客户端 / 面板唤醒 fd 任一来事立刻醒
```

- **以核心为准**：引擎全部就绪后才拉面板；面板崩了不影响注入（看门狗按 3 次/分钟上限重启）。面板**一直**起不来也
  **不会最终放弃**：稳定态是每 ~60s 再来 3 次（每次间隔 ~3s），一直重试下去 —— 细节见 `docs/CODE_WALKTHROUGH.md` 的看门狗一节。
- **无命令通道**：核心与面板之间只有共享内存（状态只读段 / 双向编辑段 / 事件环），
  唯一的"请求"是面板停引擎（写 `stop_req` + 给校验过的 `core_pid` 发 `SIGTERM`）。
- **fd 卫生是硬性项**：面板绝不继承带 `EVIOCGRAB` 的 fd（`FD_CLOEXEC`；子进程里显式清共享内存
  fd 的 CLOEXEC），否则核心退出后物理触摸回不来。

## 转屏

核心恒为竖屏坐标系、不感知旋转；面板按当前朝向绘制与命中。转屏走**双图层原子翻转**：
转屏时给备用图层按新尺寸准备、画满两帧，然后**一个事务**里旧层 `alpha→0`、新层 `alpha→1`，
SurfaceFlinger 原子提交 → 屏幕无空白。备用方案 `VTOUCH_UI_ROT_MODE=hide`（单图层遮挡换绑）。

区域**跟随视口**（默认，2026-10-03 口径）：转屏 / 启动时面板按当前方向重算每条区域的坐标
（保持「以当前方向左上角为原点的 xy」不变 —— 显示与命中同时跟着新方向走），并把基准帧写回
`regions.conf` 的 `#frame`（重启后按同一帧解释、不偏移）。旧档「区域粘在玻璃上（坐标不动）」：
`VTOUCH_REGION_ROT=off`。

## 线协议（loopback WS，一行一条命令，单客户端，新连接踢旧连接）

| 命令 | 应答 | 说明 |
|---|---|---|
| `ping` | `pong` | 探活 |
| `res` | `res <宽> <高> raw <xmin> <xmax> <ymin> <ymax> phys <物理槽数>` | 逻辑尺寸、内核轴量程与物理槽数。末段 `phys <n>` 给客户端定**物理槽**的槽数（`src/vt_ws.c:504-507`）：`onTouch(slot, …)` 的合法 `slot` 就是 `0..n-1`，物理触摸流 `phys_ev` 也只报这一段 |
| `reset` | `ok` / `err frame` | 抬掉全部虚拟触点（帧中途拒绝） |
| `down <slot> <x> <y>` | `ok` / `err point` | 按下（各自成一帧） |
| `move <slot> <x> <y>` | `ok` / `err point` | 移动（各自成一帧） |
| `up <slot>` | `ok` / `err point` | 抬起（各自成一帧） |
| `begin_frame` / `point <slot> <down\|move\|up> <x> <y>` / `end_frame` | `ok` / `err frame` `err point` | 一帧多指 |
| `points <n> <slot> <down\|move\|up> <x> <y> …` | `ok` / `err point` `err frame` | 一帧多指的**单命令**版（n 组；语义同上面三条，但先全校验再一次性提交） |
| `region add <id> <0矩形\|1圆形> <a1..a4> <0\|1>` | `ok <总数>` / `err region` | rect: `x1 y1 x2 y2`；circle: `cx cy r 0` |
| `region list` | 每行 `region <id> <type> <a1..a4> <en>` + 末行 `end <n>` | **一条区域一帧**，末行单独一帧（见下方口径） |
| `region clear` | `ok 0` | 清空 |
| `sub [phys\|region\|all]` / `unsub` | `ok` / `err sub` | 订阅通道：裸 `sub` = 区域通道（与改动前一致）；`sub phys` = 物理触摸流；`sub all` = 两条 |
| `phys_ev <ev> <slot> <x> <y> <ms>`（推送） | — | 物理触摸流：按 slot 的 `down/move/up`，不按区域过滤；追手指用它 |

上表里 **`ping` / `reset` / `region clear` / `sub all` 保留作调试口**（手工排障用）—— 仓库已无内置客户端，改这几条没有"客户端兼容"压力。

`region list` 的**分帧口径**（现役）：

- **一条区域一帧**，末行 `end <n>` **单独一帧** —— 客户端按行解析即可（逐帧读、按 `\n` 切行）。
- 行格式逐字不变：`region <id> <type> <a1> <a2> <a3> <a4> <en>`；`end <n>` 里的 `n` 是区域总数。
- **长度口径**：单帧不再受旧的 1024 字节上限影响（一条一行、各自成帧），32 条满表也不会丢表尾；
  `region add` 的 resp 仍是**单行** `ok <总数>` / `err region`。
- **队列满时的口径**：这一族走「**满了就丢这一帧**」（`outq_push_text_keep`）、**不挤掉已排队的数据**
  （事件流的策略相反：满时丢最旧、保新鲜）。所以出站队列真满时回包**可能少行、也可能连 `end <n>` 一起丢**
  （核心同时打一条 `region list 有 N 行因出站队列满被丢弃`）——客户端拿 `end`/行数或超时对账即可发现
  （客户端拿 `end`/行数或超时对账即可发现）。
- **没有 WS `region del` / `region rename`**：单条区域的删/改名在**面板**上做（面板把编辑投进共享内存
  邮箱，核心主循环这一轮就吃掉）；外部客户端要改就 `region clear` 清空重加，或 `region add` 同 id 覆盖。

推送（单向，混在同一条 WS 里），两条通道：

- `region_ev <id> <ev> <slot> <x> <y> <ms>`（订 `region`）—— 区域事件，`ev` ∈ `down/enter/move/exit/up`：
- `phys_ev <ev> <slot> <x> <y> <ms>`（订 `phys`）—— **物理触摸流**：按 slot 报 `down/move/up`，
  不按区域过滤。想「某手指在区域内按下 → 跟它到抬起」就用它：记住 `down` 的 slot，
  之后按 slot 过滤这条流（区域流做不到 —— 手指出了区域就只有 `exit` 了）。
  只报物理手指（虚拟触点不进这条流，所以一边跟一边注入不会自激）。

`region_ev` 说明：

- 末尾 `<ms>` 是**事件发生的墙钟毫秒**（墙钟基准，可直接做差）；
  它由事件自己的时间戳换算而来，是「手指那一刻」而不是「脚本收到那一刻」，
  所以 `up - down` 就是真实按压时长，`Date.now() - t` 是送达延迟。

- `down` 只在**按下那一刻就命中**时发；`enter`/`exit` 是跨边界；`move` 是区内移动且位置变了；
- `up` 在**抬起时此刻在区域内**就发 —— 包括"从区域外滑进来再抬起"（这种 `up` 没有配对的 `down`，
  要配对就用 `enter` ↔ `up`）；滑进来又滑出去在外面抬起时只有 `exit`，没有 `up`。

它**只由物理手指产生** —— 虚拟触点不进转发队列，这就是"回触不会自己触发自己"的保证。
另外：**起手那一下落在面板矩形里**的手会被锁存吞掉（核心日志打 `面板吞掉 slotN @x,y`），
整段手势不进区域判定 —— 所以"贴着面板起手再滑进区域"不会有任何区域事件。

## 坐标与身份

- 坐标是**竖屏逻辑坐标**（上面的尺寸那套）；raw 轴量程由内核给出，转换在 `src/vt_util.c`。
- 身份两段、静态分配：物理触点 `slot = tracking_id = 物理槽号(0..phys_slots-1)`，
  虚拟触点 `= phys_slots + 客户端槽号`（10 槽机器 → `10..19`）。两段不可能撞号，所以没有避让表，
  物理手指也永远不会被虚拟顶掉。
- 天花板：Android pointer id 是 32 位 BitSet（上限 31）；`phys_slots + vslots - 1 > 31` 时
  超出的部分由框架自分配。

## 退出码

| 退出码 | 含义 |
|---|---|
| `2` | 逻辑尺寸拿不到（`wm` 不可用且没给 `-w/-h`）/ 扫不到 Type-B 触摸屏 |
| `3` | uinput 建不起设备 |
| `4` | 打不开触摸设备 |
| `5` | `EVIOCGRAB` 失败 |
| `6` | 端口被占（127.0.0.1:27183） |
| `7` | 区域线程创建失败 |

启动顺序是 **先起监听 → 最后 grab → 区域线程再最后 → 面板最后**：任何失败路径都不会留下
"抓着触摸却没人能控制"的状态。

## 怎么自己验一轮（都在命令行里，不需要额外脚本）

```sh
sh scripts/ui-deploy.sh status                 # 核心/面板 pid、面板 fd 卫生（触摸设备 fd 必须 0）、日志尾
su -c 'grep -i 6a2f /proc/net/tcp'             # 27183 在听：0100007F:6A2F（状态 0A=LISTEN / 01=有客户端）
su -c 'ls -l /proc/$(pidof vtouch-ui)/fd'      # 面板：memfd:vtouch-shm 有、/dev/input/event* 没有
```

**别用裸 `nc` 验协议**：核心只认 WebSocket 握手，`printf 'res\n' | nc -q1 127.0.0.1 27183` 会被判
握手失败并关连接（收到 EOF、核心日志多一条 `ws 握手失败`）—— 核心自己的日志（`engine=on` 等）就能看出主循环是活的。

## CI（GitHub Actions）

`.github/workflows/build.yml`：push 到 `master`（或打 `v*` tag）时在 `ubuntu-latest` 上构建 ——
JDK 17 + build-tools 34.0.0 + platforms;android-24 + NDK r27d + 自拉 imgui v1.91.8，
产出三样并作为 artifact 上传：

| 产物 | 说明 |
|---|---|
| `build/vtouch.sh` | **su 脚本**：自包含单文件（核心二进制内嵌其中），推 `/sdcard/vtouch.sh` 即用 |
| `build/vtouchd` / `build/vtouchd_ui` | 默认核心 / 带面板核心 |

`scripts/ci_check.py` 是硬门（本地也能跑）：断言四个产物齐全、面板是 **real 模式**（不是 `ui_stubs.c` 的桩版）、
**su 脚本内嵌负载与带面板核心逐字节对账**（换核心没重打包 → 判红）。
所以 artifact 里不可能混进旧副本或桩版面板 —— 这也确实抓住过一次：workflow 漏 `VTOUCH_UI_CORE=real`
时发出去的就是"面板不接核心"的桩版，现在有门挡着了。

（CI 与本机构建只在 `.comment` 段（编译器版本串）不同，代码各节逐字节一致。）

## 已知边界

- **单客户端**：新连接踢掉旧连接；被踢的一方要自己发现。
- **区域判定只认物理手指**：虚拟触点不产生 `region_ev`（防自激的设计，不是缺失）。
- **`move` 只在位置变化时报**：同位置重复推不算事件。
- 注入与物理同一坐标时会两根触点共存（按坐标判定的应用表现为"等注入结束才弹起"）。
- **不开机自启**：核心是手工/脚本起进程，重启后需要重新起。
- 面板的层不参与触摸判定：面板矩形由核心按当前朝向换算后在区域判定里吞掉对应触摸。
