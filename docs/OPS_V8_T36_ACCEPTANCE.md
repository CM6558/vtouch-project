## 血泪（本轮修复/教训）

1. **又栽「拒收样板线」**：zt5/zt9 首版从 v6b-payload 里抄了 `step 14 0 2390 735 …` —— 那是**拒收测试的样板**（x>1439 竖屏逻辑越界，V6B 早已记录：条件点坐标域 0..1439）。改用祝福写法 `@(5,6)` 恒假 + 否则支路。**教训：抄载荷先核对它原来的「预期结果」列，别只看形状。**
2. **pilot 文件命名协议**：扫描认 `ops-prog-<名>.vtbc` 前缀；首轮铺了裸名 `ztp2.vtbc` → 零注册、全 `操作不存在`。命名即协议，部署脚本随协议走。
3. **停起驱动要 pid 校验**：连续四五轮出现「stop/start 未生效、旧核在跑、日志累积」——驱动加「新 pid ≠ 旧 pid」校验后 18/18 稳定。
4. **execute_code 缓冲**：逐轮结果不 `flush` → 300s 超时杀核后证据全丢（白跑一轮）。**长循环写证据：每轮 flush，并分段跑（<300s/段）。**
