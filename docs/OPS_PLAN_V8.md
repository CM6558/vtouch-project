# OPS_PLAN_V8 —— 操作语言化（真脚本 + 可视化）

> 状态：v0.1 待拍板（2026-10-10）。拍板后另落任务级 `OPS_IMPL_PLAN_V8.md`（Native 逐任务）再动代码。
> 关联与取代：`OPS_PLAN_V7.md`（路线二）——**载体部分（步骤表内做函数/表/编译缓存）由本方案取代**；
> **语义部分（表达式 v2 语法、函数/表/字符串语义、验收方法学、性能判据口径）并入本方案、继续有效**。
> 决策链：三条路线对照（增量 / 窄切口② / 语言化③）→ 拍板② → 用户改选「直接语言化」→ 本方案。

## §0 一句话目标

操作的可信源从"10 字段步骤表"升级为 **vt-script 脚本**（自研小语言，语句集 = 现有步骤词汇 + 函数/表/字符串），
编辑器提供 **文本 ⇄ 可视化** 双视图；编译只发生在编辑器（Java），核心换成 **字节码 VM** 执行；
"所有基本语法"打满（V7 遗留的唯一形态边界——函数组合式调用——在 VM 里自然消失）。

## §1 目标：覆盖清单（对 V7 §1 的更新）

- V7 更新说明：**函数组合式调用 `g(f(x))` 从"形态边界"变为"支持"**（VM 里调用就是普通指令）；
  **注释**从 N/A 变为"支持（脚本形态天然有）"。
- 结论：通用基本语法 15 类里 **13 类落地**，仅 2 类不做：异常处理（try/catch，留口）、OOP/模块（留口）。
- 语言要素一览：变量/赋值、算术（含 %）、比较、逻辑、字符串（字面量/拼接/函数库）、布尔、
  条件（if/else）、循环（次数/时长/无限/到条件 + for 糖 + 循环索引）、跳出/继续（N 层）、
  函数（定义/参数/返回/*组合式调用*/递归≤8）、数组（表）、注释、IO（触摸动作 + 提示/框选）。

## §2 不可协商项对账

1. **单前端纪律（新，替代"三端同尺"）**：语言实现（词法/语法/编译/校验/格式化）**只在编辑器一份（Java）**；
   核心**不含解析器**，只做字节码验证 + 执行；面板 = 不透明透传。历史痛点"双端逐字镜像"（Expr/名字规则）
   在语言规模下会失控，故改为单点实现 + 字节码验证器兜底。
2. **核心不读写 conf 纪律保持**：核心仍无盘上 I/O；程序载入 = 面板读文件（不透明字节）→ SHM 邮箱重放；
   编辑器 = 唯一写方（写脚本源 + 编译产物 + 镜像 schemes）。
3. **安全边界（root 引擎）**：脚本不开放文件/网络/进程原语（只开放触摸/视觉/流程/数据）；
   核心侧字节码**验证器**：魔数/版本/跳转目标/常量与名字表引用/寄存器界/指令数上限/栈平衡，一项不过按条拒收（`程序非法`）。
4. **旧端兼容**：旧 app 读 v8 数据 = 显式提示"需新版应用"（只读不毁）；旧核心/旧面板整份按版本门处理
   （行为是"弃文件"，所以**降级路径 = 用迁移备份还原**，文档明示）。
5. **性能纪律**：能提前做的（名字→槽号、跳转地址、常量折叠、表达式编译）一律编译/载入期；
   运行期"定长直索引 + 跳转 + 调函数"；重活（找图/注入/等待）函数原样复用。
6. **执行器单线程/主循环节拍**：VM 与现执行器同款"可让出"模型（等待类指令设 deadline 让出，主循环节拍不变）。

## §3 语言规范（vt-script v1 草案，细节 T0 定稿）

**文件与元数据**：一个 `.vts` 文件 = 一个操作；文件名即操作名（同 v11 名字尺子）；
文件头可选声明——`#门控 开关A`、`#自动关 开`；注释 `#` 到行尾。

**关键字草案（全中文系，与现 UI 词汇同源）**：

| 类别 | 语句/关键字 | 对应现状 |
|---|---|---|
| 动作 | `点按 x y [按住=ms]`、`滑动 x1 y1 x2 y2 [时长=ms] [停1=ms] [停2=ms]`、`等待 ms`、`按下 x y`、`弹起` | 1..5 |
| 赋值 | `名 = 表达式`（首次出现即定义；变量数上限放开为 64，拍板⑥） | 计算步 9 |
| 条件 | `如果 表达式 { } 否则 { }`（条件 = 表达式，含视觉/判定函数） | 6/7/14/15/16/19 |
| 循环 | `循环 N { }`、`循环 ms { }`、`循环 无限 { }`、`当 表达式 { }`（while）、`直到 表达式 { }`（until）、`for i = a 到 b { }`（糖） | 12/13 + 索引 |
| 跳转控制 | `跳出 [层数]`、`继续 [层数]`、`终止 [中止]`、`返回 [表达式]` | 17/18/20 |
| 函数 | `函数 名(参数…) { }`、调用 = `名(实参…)` 或 `结果 = 名(实参…)`（**组合式调用可用**） | 新 |
| 数据 | `表 名[64]`、`名[下标]`、字符串一等的（`"文本"`、`+` 拼接、`len/str/num`） | 新 |
| 展示 | `提示 "模板 {名}" [ms]`、`框区域 "r1" [ms]`、`框矩形 x1 y1 x2 y2 [ms]` | 21/22/23 |
| 表达式 | = V7 表达式 v2 全量（`%`、比较、逻辑、字符串、函数库、布尔）+ **视觉/判定函数**：`找图("模板"[, @区域, 阈值=, 持续=])`、`找色("点集"[, @区域, 模式=])`、`在区域("r9", x, y)`、`开关开("s1")`、内建只读 `轮` | 判定族并入表达式 |

**示例（同一操作，两视图等价）**：

```vt
# 吕布 · 补刀循环
#门控 开关A
如果 在区域("r9", tx, ty) { 点按 tx ty 50 } 否则 { 等待 200 }
循环 3 { 点按 700 1600 50; 等待 250 }
x = tdx + cos(30) * 120
直到 花费 >= 100 { 补刀(); 花费 += 1 }
直到 找图("攻击键", @战斗区, 持续=3000) { 等待 100 }   # 命中即退出（fx/fy 已写）
提示 "第 {轮} 轮 · fx={fx}" 2000

函数 补刀() { 点按 fx fy 50 }
```

**语义要点**：找图/找色等视觉函数是**布尔表达式**（命中写真 fx/fy、返回 1）；持续查找 = 参数；
条件块不再有"四档（继续/跳过/跳转/中止）"的文本糖——统一为 if/while 结构（编译期消灭歧义）；
`终止` = 现 20 的两模式；运行时错误（无值/类型错/下标越界/调用超深）→ 中止 + **行号报告**。

## §4 运行时设计（核心 VM）

**字节码容器**：魔数 `VTBC` + 版本 + 源哈希 + 常量表（数值/字符串）+ 名字表（变量/表/函数）+ 行号表 + 指令流。
紧凑编码（1 字节操作码 + 定长/变长操作数），典型"点按 100,200,50"≈ 十几字节。
每操作上限 **32KB**（推荐；≈ 现 512 步容量的数倍；受区 B 81920 载荷约束，拍板⑦⑧）。

**指令集（~45 条，语义 = 现执行器逐条平移 + 计算）**：

- 常量/数据：`PUSH_NUM PUSH_STR PUSH_TRUE/FALSE`、`LOADV/STOREV`（变量槽）、`LOADT/STORET`（表+下标）、`轮` 读取
- 运算：算术 5 + 比较 6 + 逻辑 3（短路用跳转）+ `NEG/NOT`
- 控制：`JMP`、`JZ/JNZ`、`CALL/RET`（帧：返回地址、参数、结果）、`BREAK/CONT`（编译成跳转）
- 动作：`TAP/SWIPE/WAIT/DOWN/UP`（参数 = 寄存器/常量）
- 视觉/展示：`FINDIMG/FINDCOLOR`（结果压栈 + 写 fx/fy）、`HL/BOX/TOAST`
- 收尾：`FINISH/ABORT`；守卫：全局指令预算（防死循环，替代/并行 200 跳守卫）+ 中止检查在指令边界

**执行模型**：可让出 tick——等待/动作/视觉指令设 deadline 后让出（与现"拍"机制等价）；
纯计算段每拍有指令预算（推荐 2000 条/拍，可调，拍板⑩），防饿死主循环与输入处理。

**验证器（核心侧，收程序时跑一次）**：结构扫描全部跳转落点、栈深平衡、寄存器/常量引用界、
指令数 ≤ 上限、调用深度声明 ≤8；不过 = `程序非法` 按条拒收（整条操作不动，不毁其余）。

**状态/诊断**：`pc` + 行号表 → `op_run_line`（运行到第几行，面板/未来监视用，拍板为 v8.1 可选项）；
日志族沿用 `op ` 前缀 + 行号；TRACE 同款开关。

## §5 存储 / 契约 / 热载

- **盘上布局（拍板⑦）**：`schemes/<方案>/` 内新增 `progs/` 目录——`<操作>.vts`（源码，可信源）+ `<操作>.vtbc`（编译产物）；
  `ops.conf` 升 **`#vtouch-ops v8`**：只存元数据（操作名/门控/自动关/产物哈希/大小）。live == schemes/current 不变量照旧由编辑器维护。
- **契约（一次升）**：`VT_SHM_VERSION 16 → 17`（V7 未落地不占号）；`struct vt_op` 的 `steps[]` 换成程序容器
  `{ name, gate, auto_off, prog_len, prog[≤32KB] }`。区 A 操作表：16 × ~33KB ≈ 0.5MB（比现 1.2MB 更小）；
  区 B 编辑载荷 ≤ 32KB + 元数据 ≪ 81920 ✓。`vt_step`/旧步骤结构退役（由 V8 执行器取代）。
- **载入链路**：启动/热载 = 面板读 v8 元数据 + 读取 `progs/*.vtbc`（**不透明字节**）→ 邮箱重放 → 核心验证后上表。
  面板 load/save_ops（现 `vtouch_ui.cpp:936/:1047` 的逐字段解析）改为"透传搬运"（改动面小但真实存在）。
- **热载 T8**：mtime 观察对象 = ops.conf + progs 目录 → 防抖重放（链路与现口径一致）。

## §6 双视图机制

- **起步（推荐，拍板⑨）＝单模锁定**：每个操作 ∈「可视化模式 | 脚本模式」，保存时定锁。
  块 → 脚本 = 一键生成（无损）；脚本 → 块 = 解析，落在可视化子集内即可切回，否则提示"含可视化表达不了的写法"。
- **进阶（V8.x）＝规范格式双向**：AST 唯一真相；文本保存时按规范打印重排（注释挂节点）；两视图实时同编。
- 可视化 = 现有卡片/块编辑器演进（AST 比步骤表更强，渲染链大量复用）；文本编辑器 = 语法高亮/缩进/错误行标红。
- 手机上打字体验差 → **块仍是一等公民**；文本主要服务：批量编辑、**AI 直接读写操作**、diff/分享/版本。

## §7 性能账（判据化）

**现状基线（实测）**：纯空体循环 ~0.3µs/轮（2 秒 650 万轮）；真实操作由重活主导（找图 ms 级、注入、等待）。

**影响矩阵**：

| 场景 | 现在 | 换 VM 后 |
|---|---|---|
| 找图/找色/等待/注入 | 抓帧/匹配/注入主导 | **不变**（同一批 C 函数） |
| 计算/表达式密集循环 | 每次求值重解析（µs 级） | **更快**（编译一次、运行期栈机） |
| 纯空转循环 | ~0.3µs/轮 | 同数量级（估 10–50ns/指令，±几成） |
| 保存 | 立即 | +一次编译（手机端几 ms 一次性） |
| 载入/热载 | — | +一次验证（μs–ms） |
| 内存 | 74.8KB/操作 | 通常几 KB（≤32KB） |

**验收判据（T3 硬门）**：① 同场景"步骤版 vs 脚本版"双跑对拍，行为逐条一致；
② 空转基线复测波动 ≤10%；③ 找图场景端到端耗时差 ≤1%；④ 编译 + 验证耗时报告（典型脚本 <10ms 量级）。

## §8 迁移

1. **翻译器（T5）**：steps → vt-script 逐类型机械翻译（含块/子条件/函数留口），跑现有**全部方案与 zt 用例**对拍（同场景行为一致）。
2. **备份**：迁移前全量 `*.bak-v8`（含 schemes 全部）；迁移=一次性 + 人工抽查 + 报告。
3. **降级路径**：新数据回滚旧核/旧面板 = **用备份还原**（旧端对 v8 的行为是"整份丢弃"，不可逆，必须在文档与迁移报告里明示）。
4. **旧编辑器**：Ops 解析加 v8 版本门 → "需新版应用"提示（只读不毁）；新版编辑器与迁移同批发布。

## §11 风险与对策

- **双视图体验**（最大风险）：单模锁定起步，砍掉往返格式化的复杂度；块体验不回退（现有渲染链复用）。
- **验证器质量**：字节码是唯一进核心的载体 → 验证器用例独立成组（恶意/畸形构造 ≥30 例）。
- **迁移对拍工作量**：翻译器 + 全方案对拍 = 一个大任务；先跑 zt 家族再跑用户方案。
- **面板改造面**：load/save 透传化 + 热载观察对象扩展；面板与核心同构建发布，版本门兜底。
- **降级不可逆**：靠备份 + 文档明示管理（旧端 v8 行为"整份丢弃"，不做额外兼容层）。
