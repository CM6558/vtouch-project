# 视觉功能（找图 / 找色）spec — v0.1 草稿（待评审）

> 目标：给 vtouch 增加「看屏幕」的能力 —— 操作步骤里能「找图」「找色」，
> 结果进结果槽、接现有四档条件分支。全屏按**当前分辨率**（原生）查找。
> 前置：抓屏层已真机实测（见 §2，按需 `captureDisplay` 4–7ms/次）。
> 状态标记：【实测】= 已有真机证据；【待定】= 需评审拍板；【预留】= 二期。

---

## §1 目标与范围

### v1 交付
1. **抓屏层**：面板进程按需抓一帧（`ScreenCapture.captureDisplay`，原生分辨率、当前方向），进共享内存帧区。
2. **匹配引擎**：核心内自写 C + NEON（含标量回退）——找色（含多点找色）、找图（模板匹配）。
3. **操作步骤**：新增「找图」「找色」两类步骤，参数在面板编辑；结果（命中坐标）进结果槽 r1/r2；语义 = 现有四档条件（继续 / 跳过 / 跳转 / 中止）。
4. **模板 / 点集管理**：面板内「截帧 → 框选 → 存模板」；存储 `/data/local/vtouch-runtime/templates/`（重启保留、方案内共享）。
5. **契约 v7 → v8**（帧区 + 步骤新字段）；**ops.conf v4 → v5**（新步骤行编码）；读端兼容。

### 明确不做（二期预留）
- 常驻热镜像 / 连续帧流 / 跟踪窗口（实时跟踪）——本机已证镜像会触发平台死锁（3/3），见 §2.4。
- GPU 加速、多模板批量、旋转不变匹配、透明色掩码。
- 视觉触发（区域触发以外的新触发源）。

### 硬约束
- 零依赖交付形态不变：不链 OpenCV；NEON 引擎自写（含标量回退，编译期按 `__ARM_NEON` 分支）。
- 默认（无 UI）构建不引入任何新代码（`#ifdef VT_UI` 守卫纪律，同 v5）。
- 坐标契约：一切对外坐标 = **竖屏逻辑帧**（现有契约）；帧像素坐标 ↔ 逻辑坐标的映射由帧区头部携带的方向信息完成（§3.3）。
- 性能目标（§10）为验收硬指标。

## §2 抓屏层（面板进程）

### 2.1 主路径：按需 `captureDisplay`【实测】
- 面板（root app_process + systemMain）内：
  1. **display token**：binder 直连 `SurfaceFlingerAIDL`（`android.gui.ISurfaceComposer`）——
     - 事务码 **6** = `getPhysicalDisplayIds()` → 物理屏 id（本机 `4630946756802996883`，亦可 `dumpsys SurfaceFlinger --display-id` 解析兜底）；
     - 事务码 **7** = `getPhysicalDisplayToken(long)` → `IBinder` token；
     - 回复头有 **4 字节状态前缀**，读前 skip 4B。
     - （Android 16 已删 Java 层 `getPhysicalDisplayToken`/`getInternalDisplayToken`；接口类不可反射加载 —— 只能用 binder 事务。）
  2. `ScreenCapture$DisplayCaptureArgs$Builder(token).build()` → `ScreenCapture.captureDisplay(args)` → `ScreenshotHardwareBuffer`。
  3. **JNI 读回**：`AHardwareBuffer_fromHardwareBuffer` → `AHardwareBuffer_lock(CPU_READ)` → memcpy 进 shm 帧区（跳过 Java 位图路径；实测 Java `copy(ARGB_8888)` 要 60–114ms，弃用）。
- **实测数字**：capture 调用 4–7ms/次（首次预热 25–84ms）；**100 连抓：avg 8.5ms / p95 10ms / 持续 110fps**（竖横屏一致）；帧 = 当前方向原生 RGBA（竖屏 1440×3168 / 横屏 3168×1440，已实测两向）；JNI 读回预计 +5–10ms（【实现期实测】）。

### 2.2 请求-应答协议（核心 ↔ 面板）
- 操作执行在**核心主线程**（vt_ops.c），抓帧在**面板**。协议（shm 帧区头 + 唤醒）：
  1. 核心需要帧 → 写「抓帧请求」序号 + 唤醒面板；
  2. 面板抓帧完成 → 写帧（双缓冲）+ 序号 + 完成标志 + 唤醒核心；
  3. 核心校验序号 → 读帧 / 超时。
- 唤醒机制【待定】：v1 = 面板帧循环内轮询请求标志（≤16ms 附加延迟，实现最简）；优化 = 专用 pipe/eventfd。
- **超时**：请求发出后 N ms（默认 1000【待定】）无完成 → 步骤中止，新中止词 **「无画面」**。
- 面板不在/已死 → 立即「无画面」（不等待）。

### 2.3 降级链【待定：v1 是否实现】
- `captureDisplay` 失败（异常/超时）→ 重试 1 次 → 仍失败 → **`screencap` exec 兜底**（独立进程，PNG 49ms/raw 409ms 实测；PNG 需解码【v1 简化：raw 直读? 18MB 写文件 409ms 太慢——PNG+解码 ~60-70ms 或 `screencap` 管道直读 raw】）。
- v1 建议：**只做 captureDisplay + 失败即「无画面」**；screencap 兜底排 v1.1（除非评审要求 v1 就带）。

### 2.4 安全边界（为什么不做镜像）【实测】
- 常驻热镜像（`createVirtualDisplay(AUTO_MIRROR)` + ImageReader）在本机（ColorOS 16）**3/3 触发平台死锁**：system_server 的 `AbsAppSnapshotController` 卡在 SF `captureLayersSync` → WMS/AMS 双锁级联 → 看门狗杀进程（事故复盘见台账 `progress.md`）。
- `captureDisplay` 是**普通应用路径**：不持 WMS 锁 → 最坏情况 = 我们自己的调用超时（走「无画面」），不会死锁系统。**安全性已 20 分钟观察窗验证**（观察记录 `build/probe/observe_cd.log`）。
- FLAG_SECURE 窗口：抓帧返回黑帧或失败【待实测】→ 匹配自然不命中；不特殊处理。

## §3 帧交接（共享内存）

### 3.1 帧区布局（契约 v8 新增第 4 区）
```
struct vt_shm_frame_hdr {          // 帧区头（面板写 / 核心读）
    uint32_t magic;                // 'VFRM'
    uint32_t version;
    volatile uint32_t seq;         // seqlock：奇 = 写入中，偶 = 稳定
    uint32_t width, height;        // 帧像素尺寸（当前方向！）
    uint32_t stride;               // 行跨距（字节）
    uint32_t format;               // 0=RGBA8888
    uint32_t rotation;             // 抓帧时屏幕方向（0/1/2/3）
    uint32_t req_seq;              // 已完成的抓帧请求序号
    uint32_t req_pending;          // 核心写：请求序号（0=无请求）
    uint32_t flags;                // bit0=帧有效 bit1=抓帧失败(错误码)
    int32_t  err;                  // 失败码
    uint64_t ts_ns;                // 抓帧完成时刻（单调钟）
};
// 后随 2 块帧缓冲（双缓冲，各 MAX_W*MAX_H*4 字节，按需映射/惰性缺页）
```
- 缓冲尺寸：**动态**——按当前分辨率（1440×3168×4 = 18.2MB/块，双缓冲 ~36MB）。memfd 惰性缺页，实际占用随用随增。【待定：双缓冲 vs 单缓冲+seqlock；倾向双缓冲】

### 3.2 读写纪律
- 面板写：seq++（奇数）→ 写数据 → seq++（偶数）+ ts/尺寸字段。
- 核心读：读 seq → 读数据 → 再读 seq，变化则重试（有界重试 N 次，失败按「无画面」）。
- **按需拷贝**：核心只在步骤执行时读帧；读进核心侧临时缓冲（或直接原地匹配，匹配只读不改帧）。

### 3.3 坐标映射（帧像素 ↔ 竖屏逻辑）
- 帧 = **当前方向**的物理像素（例：横屏游戏时 3168×1440）。**【实测确认】旋转锁 1 后 captureDisplay 返回 3168×1440**（帧随当前方向翻转，坐标映射设计必要且口径成立）。
- 映射：`frame(x,y) → 逻辑(lx,ly)` 按 `rotation` 做逆旋转 + 缩放（物理 vs 逻辑通常 1:1，但保留缩放因子字段）。
- 规则：**逻辑帧永远竖屏**（现有契约不变）；横屏时命中的帧坐标经逆旋转回竖屏逻辑坐标再进结果槽。
- 反向（逻辑 → 帧）用于区域限定搜索的矩形换算。

## §4 匹配引擎（核心，`src/vt_vision.c`，VT_UI 守卫）

### 4.1 预处理
- 帧就绪后按需构建：**灰度**（NEON，18MB→4.6MB，~1ms）+ **1/2、1/4 金字塔**（~0.3ms）。
- 找色直接用 RGBA（保色相）。

### 4.2 找色（`OP_STEP_FINDCOLOR`）
- 单点：`(x,y)` 处像素与目标色距离 ≤ 容差（per-channel 或欧氏【待定，倾向 per-channel max-diff】）。
- **全屏扫描**：NEON 一次比 8/16 像素（vabdq_u8 + 归约），**命中即停**；区域限定时只扫区域内。
- **多点找色**：基准色 + N 个「偏移→颜色」参考点（N ≤ 16【待定】）——全屏找基准色命中后验证参考点，全对 = 命中。命中即停（首个命中）。
- 输出：命中坐标（首个）进结果槽 r1=x、r2=y；未命中 → 不成立侧。

### 4.3 找图（`OP_STEP_FINDIMAGE`）
- 算法栈（按性能证据选型）：灰度 SAD + **行级早退（SSDA）** + NEON `vabaq_u8` 累加 + **金字塔粗→精**（1/4 粗搜 → 1/2 → 全分辨率精修）+ 命中即停。
- 模板：灰度、尺寸 ≤ 屏幕 1/2【待定上限】；匹配步进 1px（精修）；粗搜步进 = 金字塔比例。
- 相似度阈值：**平均绝对差 ≤ T**（默认 T=8/255【待定】），面板可调。
- 输出同上：命中坐标进槽；未命中 → 不成立侧。

### 4.4 执行位置与并发
- 匹配跑**核心工作线程**（独立于主循环）【待定：v1 是否直接在主循环内同步跑——若全屏找图 ≤5ms 达成则主循环内同步最简单】。
- 一次一条操作（现有约束不变）；视觉步骤在操作步序内同步阻塞（有超时）。

## §5 模板 / 点集管理

### 5.1 存储
- 目录：`/data/local/vtouch-runtime/templates/`（核心/面板启动不清理；随方案共享【待定：是否随方案隔离】）。
- 模板文件：`<名>.tmpl` —— 自定义头（magic/版本/宽高/方向/灰度数据）【待定：或直接 PNG 由面板解码】。
- 点集文件（多点找色）：`<名>.pts` —— 基准色 + 参考点列表。
- 命名规则：与区域 id / 操作名同尺子（`vt_id_ok` 同款：`[A-Za-z0-9_-]`、1..15）。

### 5.2 截取流程（面板）
1. 模板管理页「截取」→ 抓一帧（复用 §2）→ 面板内显示（缩放预览）；
2. 手指框选矩形 → 命名 → 存盘；
3. 模板记录**抓帧时的方向**；匹配时若当前方向不同 → **模板旋转 90° 对齐**（小数组变换，成本可忽略）【待定：v1 或 v2】。

### 5.3 生命周期
- 删除/改名 = 文件操作（面板）；重名拒绝；缺失文件在步骤执行时报「模板不存在」中止。

## §6 操作步骤集成

### 6.1 新步骤类型
- `OP_STEP_FINDIMAGE = 10`、`OP_STEP_FINDCOLOR = 11`（顺延现有 0..9）。
- 字段映射（**定稿**；区域限定**复用 `expr` 列**承载区域名，空 = 全屏——承「区 B 一页 4096」断言：vt_op 3624B 已近页限，新增字段会炸；不新增步骤字段）：
  - 找图：`ref` = 模板名；`expr` = 区域限定（区域 id，空 = 全屏）；`a1` = 阈值 T（0..255）；`a2/a3/a4/ms` = 0；`j1/j2` = 成立/不成立目标（四档，与条件步同款）。
  - 找色：`a1` = 模式（0 = 单点 / 1 = 多点）；`ref` = 点集名（多点必填、单点必须空）；`expr` = 区域限定；单点：`a2` = 容差（0..255）、`a3` = 颜色（0xRRGGBB）；多点：点集文件携带基准色/容差/点表（`a2/a3` = 0）；`j1/j2` 同上。
  - 颜色**不内联点集**：多点只走点集文件（`.pts`）。

### 6.2 结果与分支
- 命中：r1 = x、r2 = y（逻辑坐标，可直接被后续步骤/计算引用——现有槽引用 -6..-9 天然复用）。
- 四档语义 = 现有条件步同款（成立 / 不成立 → 继续 / 跳过 / 跳转 / 中止）；中止词（**定稿**）：
  - 不成立侧中止 → **「未命中」**（新词；条件步的「条件不成立」不用于视觉步）；
  - 成立侧中止 → 「条件中止」（沿用条件步词）；
  - **「无画面」**（抓帧失败/超时/面板不在）；
  - **「模板不存在」**（模板/点集文件缺失）；
  - **「视觉错」**（内部错误：缓冲损坏/尺寸超限/参数越界）。
- 起跑清零：r1..r4 现有语义不变（视觉步骤按序覆盖）。
- 按住期间：**允许**找图/找色（纯读屏不碰手指，与计算同类）。

### 6.3 面板编辑
- 「加步」区新增「找图」「找色」（现有 3×3 → 4×3【待定】或分组）；
- 找图步骤编辑：模板下拉（枚举 templates/）+ 区域下拉（枚举区域表）+ 阈值滑条/输入；
- 找色步骤编辑：颜色选择（R/G/B 输入或色板）+ 容差 + 点集下拉；
- 取点回填（现有功能）复用：找色步骤可直接用「取点」从屏幕吸色【待定】。

## §8 日志口径（`vis ` 前缀族）
- `vis 抓帧 请求 → 完成 <ms>`（TRACE 级）；
- `vis 找图 <模板> 命中 x,y (耗时 <ms>)` / `vis 找图 <模板> 未命中 (耗时 <ms>)`；
- `vis 找色 命中 x,y` / `未命中`；
- 中止词进现有 `op 中止 原因=...` 族：`无画面` / `模板不存在` / `视觉错`；
- 面板侧：`vis edit 找图 第 N 步 模板=<名> 区域=<id|全屏> 阈值=<T>` 等编辑日志。
- 高频明细默认不打（同 v5 口径）；`VTOUCH_OPS_TRACE=1` 时加 `vis 抓帧` 明细。
