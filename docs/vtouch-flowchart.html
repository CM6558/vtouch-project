05

合并帧发射 (emit_frame, vtouchd.c:272)

槽位布局: 0..phys_slots-1 物理槽 + phys_slots..phys_slots+vslots-1 虚拟槽, 同一 uinput 设备, 同一 SYN 提交 — Android 视为同一触摸面。
1物理 pending_up 槽ev_add(SLOT, i) + ev_add(TRACKING_ID, -1) — 先抬起再移动, 顺序由内核按事件序保证
2物理 down 槽SLOT + TRACKING_ID(原始 id) + POSITION_X/Y(原始 raw 值, 零精度损失) + TOOL_TYPE(FINGER)
3虚拟 pending_up / down 槽SLOT = phys_slots + i; tracking id 由 next_tracking_id 自增分配(溢出回绕 1)
4BTN_TOUCH / BTN_TOOL_FINGERany_down() = 物理或虚拟任一槽按下 → 1, 否则 0
5SYN_REPORT + 单次 writevev_n 累计 ≤483 事件(96 槽×5+3), iovec 上限 512; 整帧一次 writev 零碎片vtouchd.c:174,188
writev 短写?
是 (uinput 极罕见)
逐块补发剩余字节不丢帧尾; 补发也失败 → 丢弃帧返回 -1
否
清零全部 pending_up帧完成
坐标转换 (vtouchd.c:108/121): logical_to_raw: raw = axmin + logical×span/(size-1) · raw_to_logical: logical = (raw-axmin)×(size-1)/span。daemon 恒以竖屏物理坐标运行 (bundle 启动时 wm size 归一化 W<H), 客户端旋转换算见 ⑧。

区域匹配五事件 (region_match, vtouchd.c:443)

纯监听: 物理触摸始终 1:1 透传, 区域命中只推事件不拦截不代点。静态数组无分配, 纯 int 比较, 开销微秒级。同 id 重复 add = 原地更新属性(面板开关/显隐安全)。
区域表 regions[32]type 0=矩形(x1,y1,x2,y2) · type 1=圆形(cx,cy,r) · id ≤15 字符 · enabled 开关
add 校验: 区域数>32 / 非数字 / type∉{0,1} / a1≥宽 / a2≥高 / a3>100000(圆半径/矩形x2) / a4≥高 → err region, 不影响已有配置vtouchd.c:335-393
帧状态辅助表slot_in[phys][region]: 上一帧槽是否在区域内 · slot_hit: 本次按下是否命中过 · slot_last_x/y: 上次 move 推送基准
对每个物理槽 × 每个启用区域raw→logical 换算失败直接跳过 — 只读 phys[], 绝不阻塞注入路径
槽当前 down?
是 (按下状态)
上一帧未按下 = 新按下命中 → slot_hit=1 + 推 down; 记录按下位置为 move 基准
上一帧已按下 → 状态迁移判定: 未命中→命中 = 推 enter · 命中→未命中 = 推 exit · 在内且坐标变化 = 推 move (enter/down 帧不重复推)
否 (刚抬起, ps_down 还是上帧状态)
抬起且按下期间命中过 & 抬起点仍命中→ 推 up (纯监听, 不代点)
随后 slot_hit 清零 (两帧都未按下时)

WebSocket 服务与协议 (vtouchd.c:641-855)

纯 C 手写 WS (SHA-1 握手 + 帧解析), 零依赖。文本帧协议, 一帧 = 一条命令 = 一行响应。只监听回环, 单客户端, 新连接踢旧。

关键设计决策与已知陷阱

主题结论 (源码证据)
单进程合并vtouchmerge(EVIOCGRAB+uinput) 与 vtouchws(WS) 合并为一个 poll 循环 (vtouchd.c 头注释) — 消除 UDS 跳转与半死状态 (merge 活 bridge 死)。
UI 单进程整合 (定案)vtouchd 编译为 C 库 (vtouch_init/poll_step/cleanup + region_* + set_callbacks) 嵌入 app_process 渲染进程 → JNI → libtestimgui.so (EGL GLES2 + Dear ImGui) → SurfaceControl 图层。触摸/匹配/WS/面板同进程内存直连, 无 socket 转发; 脏检查渲染省 CPU; 透明合成 glClearColor(0,0,0,0) + RGBA8888; CJK 用 NotoSansCJK; AVD 需 -gpu host。
UI 方案调研结论 (docs/ui_approaches_research.md)AutoJs6 floaty 无 webview 元素 (web.md 检索 0 命中, issue #467/#273/#437) → floaty 内 WebView 出局; 独立 WebView 壳 APK (方案 B) 为主候选; 前置条件: vtouchd 多客户端改造 (现单连接踢旧)。
/sdcard noexec共享存储禁止执行 ELF → bundle 自释放必须 cp 到 /data/local/tmp/vtouchd (AGENTS.md 陷阱)。
SELinuxAutoJs6 应用上下文可能被拒访问 /data/local/tmp → 自释放路径需 setenforce 0; 真机 su 走 v8 包装器 (su_wrap.sh + sud.sh daemon + sudq 文件队列, 因 Runtime.exec("su") 是交互式 stdin)。
EVIOCGRAB 恢复崩溃后物理触摸被 grab 到 fd 关闭为止 → AutoJs6 bootWatch 重连循环 (ensure + connect + sub + pushRegions) 秒级盲窗自动恢复。
动态设备发现永不硬编码 /dev/input/eventX; 扫描 event0..63 取第一个 Type-B 多点触摸设备 (validate_device 校验 4 项 ABS_MT 能力 + 轴范围)。
sleep 阻塞事件循环AutoJs6 主线程 sleep() 会卡 WS 回调 → 所有阻塞动作 (swipe 内插值 sleep / 回触) 必须 threads.start; 读线程只负责 recv/dispatch。
虚拟触摸不自激daemon 只对物理槽做 region 匹配, 虚拟注入不产生 region_ev → 回触连击不会自我触发 (vtouch_touchback.js 注释)。
Type-A 兜底AVD virtio 触屏发 ABS_X/Y 无 ABS_MT_POSITION → physical_events 增加 ABS_X/Y 分支; 但模拟器 console "event mouse" down 无坐标、move-under-down 不更新位置 → 物理 move 需真机验证。
WAF 规避内网 HIS WAF 拦长 base64 → bundle 内嵌二进制 76 字符分行拼接 (build_bundle.py:913)。
WS 可靠性仅回环 127.0.0.1; 坏客户端只关连接 (owner_reset 复位虚拟触点), grab 不丢; 只接受 masked 文本帧; 4096B 上限; 不执行 shell; 订阅状态随连接生命周期清零。
区域监听边界region_match 在 SYN 帧注入完成之后执行 (ps_down 滞后一帧用于判定新按下/刚抬起) — 匹配绝不阻塞/修改触摸路径; onUp 条件为「抬起且按下期间命中过且抬起点仍命中」。
