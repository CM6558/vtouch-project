# OPS_PLAN_V7 —— 操作语言化一期（"所有基本语法" · 路线二）

> 状态：v0.1 待拍板（2026-10-10）。拍板后另落任务级 `OPS_IMPL_PLAN_V7.md`（Native 逐任务）再动代码。

> 用户口径：①「让操作支持所有基本语法——编程语言都会支持的那些」②「实现要合适、且性能好」③ 拍板走路线二。

## §0 背景与路线结论

- 现状盘点（对代码核实）：控制流其实已基本齐（12..20 族 + 五类判定 + 且/或/取反 ≤4）；缺的是**函数、数据（字符串/数组）、表达式补全、循环索引**。
- 三条路线的取舍（会话记录）：① 继续"新类型号"增量 = 数据类能力用步骤表达别扭、五处联动每项都来一遍；② **窄切口（本方案）**＝表达式/数据一次做成"小语言"，控制流沿用结构化块；③ 全语言化（文本⇄可视化 + VM）= 表达力天花板最高，但双端工程 + 契约大迁移 + 手机文本体验差；且 ③ 的前半段就是 ②，先 ② 后 ③ 不返工。
- 本方案目标一句话：**把"语法全不全"收敛成"表达式引擎强不强 + 数据处理能力有没有"两个问题**；每项都按"性能不进热路径"的纪律落地。

## §3 设计

### 3.1 表达式 v2（语法 + 编译式求值）

**语法（在 v1 上扩展，全部并入 `vt_expr.c` / `Expr.java` 双端同尺）**：

```
expr    := or_expr
or_expr := and_expr { "||" and_expr }
and_expr:= cmp_expr { "&&" cmp_expr }
cmp_expr:= add_expr [ (">"|"<"|">="|"<="|"=="|"!=") add_expr ]      // 非结合（链式比较拒绝）
add_expr:= mul_expr { ("+"|"-") mul_expr }
mul_expr:= unary { ("*"|"/"|"%") unary }
unary   := ["-"|"!"] unary | primary
primary := number | string | "true" | "false" | var | table "[" expr "]"
         | func "(" args ")" | "(" expr ")"
string  := '"' { 任意 UTF-8 除 '"' 与 '\'；转义 \" \\ } '"'
```

- 值域：数值（double）| 字符串（池引用）；比较/逻辑结果 = 1/0；真假判据 = 非零。
- `+`：两侧数值 = 数值加；任一侧为字符串 = 拼接（数值自动转十进制、最多 6 位小数）。`- * / %` 均数值域，字符串操作数 → `类型错`。
- 函数库（一期）：`len str num rand floor ceil round` + 现 7 个（atan2/sin/cos/abs/min/max/sqrt）；`rand(a,b)` 含端点整数。
- 边界维持：长度 ≤63 字符、括号深度 ≤8、token ≤128（上限口径不变，**这就是"表达式上限保持 63"的含义**；需要更长再单独拍）。
- 错误口径不变：编辑期拦（镜像 check）、载入期同尺拒、运行期防御兜底；新增原因词：`类型错` / `下标越界` / `字符串池满`。

**编译式求值（性能核心改动）**：

- 现状 = "递归下降解析 + 现解析现求值"（`vt_expr.c` 文件头自述）——每次求值重解析。
- 改为：**核心在"载入期"编译一次**（`VT_EDIT_OP_PUT` 过 `op_valid` 后 / 启动导入后），产出一份栈式字节码缓存（核心内存 `struct op_prog`，按 op×步；字符串字面量编译期入池；常量折叠编译期完成；名字→槽号/参数号/表号全部编译期解析）。运行期 `vt_expr_run(prog, env)` 纯栈机，无解析、无字符串比较。
- 编辑器侧只镜像**语法判定**（Java 不产字节码）；求值语义靠宿主单测（`build/test_vt_expr.c`）+ 真机用例覆盖。
- 估算：编译缓存增量 ≤ 每表达式 ~200B 上限；512 步 ×16 操作最坏 ~1.5MB，实际远低（只有带表达式的步才有 prog）。R 内存，不涉契约。
- 求值开销：栈机 ~10–50ns/原语量级（估算）；对计算密集循环是**净提升**（消掉重解析）；对空转循环零影响（无表达式则不跑）。复测基线见 §5 P0。

### 3.2 函数（新类型 24..29）

**行设计（10 字段行内消化，无格式变化）**：

| 类型 | 名称 | 字段映射 | 结构规则 |
|---|---|---|---|
| 24 | 函数定义头 | `ref`=函数名（新命名空间，同 v11 尺子）；`a1`=参数数 0..4 | 其后紧跟 a1 条 25 |
| 25 | 参数行（伴行） | `ref`=参数名（不许重名/撞预置） | 必须连续紧跟 24 |
| 26 | 函数结束（结构行） | 全 0/空 | 与 24 配对 |
| 27 | 返回步 | `expr`=返回表达式 | 体内任意处（含嵌套块内）；0..N 条 |
| 28 | 调用步 | `ref`=函数名；`a1`=结果槽（0..15 = 自定义变量槽；`-1` = 不要返回值） | 其后紧跟 N 条 29，N = 被调函数参数数 |
| 29 | 实参行（伴行） | `expr`=实参表达式（调用点求值） | 必须连续紧跟 28 |

**执行语义**：

- 执行流"路过" 24 → 跳到 26 之后（函数体不参与顺序执行）；调用 = 帧压栈 → 跳 24+1+a1（参数已按序拷入帧）→ 执行体 → 遇 27 = 表达式的值写入**调用步 a1 的结果槽** + 弹栈回调用点下一行；走到 26 无 27 = 结果槽无值（引用方按 `结果无值` 中止）。
- 调用栈：R 内 `frame[8]`（返回步号 + 结果槽 + `double params[4]` + 字符串参数引用），深度 >8 → 中止 `调用超深`（新词）；**递归允许**（受限深度）。
- 作用域：**参数 = 帧局部**（在函数体内可被读写，不污染调用方）；**自定义变量 = 全局共享**（函数内读写的就是 op 的 16 槽，符合自动化脚本直觉）；预置量（tdx/fx…）同全局。名字解析优先级（编译期定死）：参数 → 自定义变量 → 预置。
- 结构校验（`op_valid` 扩 + 编辑器镜像）：25/29 伴行连续且计数匹配；24 不得嵌套在另一函数内；28 的函数名必须已定义（`函数未定义` 拒，新词）；跳出/继续不得跨函数边界（`跳出跨函数` 拒，新词）；跳转/跳过档同"跨块"纪律一并扩展；26 缺失 = 配对错（沿用配对错族）。
- 配对/调用目标全部进 `op_pair_build`（`vt_ops.c:1329`）起跑预计算：运行期调用 = memcpy 参数 + 压栈 + 跳位（ns 级）。
- 编辑器：函数定义=新色带块（同 12/14 家族，色带第三色）；调用=单行卡片 + 结果槽选择器 + 实参行；返回=卡片。移动/复制/粘贴/跨方案复制全链适配（含"复制调用→带上被引函数定义"的依赖规则）。
- ⚠ 拍板保留项：「纯计算函数」（体=单个表达式、可被表达式编译期内联，如 `g(f(x))`）＝二期路线三的跳板，本方案不做。

### 3.3 数据与糖

- **字符串值**：变量表 16 槽值类型化（数 | 串）；字符串运行时值放 **R 内字符串池**（环形，容量拍板值 64 条 × ≤128B）；字面量编译期入池；拼接产生新池项；池满 → 中止 `字符串池满`。名字表 `vt_op.vars` 不动（16 槽不变）。**字段引用**（坐标/时长负编码）遇字符串值 → 中止 `类型错`。提示步 `{名}` 模板渲染兼容字符串值。
- **数值表（数组）**：**4 张命名表 × 64 项**。名字表 → `vt_op` 增 `char tabs[4][VT_NAME_BUF]`（+192B/op，区 B 余量 ~7KB 内 ✓）；值 → R `double tabv[4][64]`（2KB 核心内存，零契约面）。语法：读取 = 表达式内 `表名[下标表达式]`；写入 = 计算步变体（`a1=-2`、`ref` 空、`expr` = `表名[下标] = 表达式`，校验左右两侧）。越界 → `下标越界`；起跑清零（同变量）。
- **循环索引**：预置只读变量 `轮`（拍板名，默认 `轮`）= 当前最内层循环已完成轮数（拍板基数，默认 **0 起**）；嵌套取最内层；循环外引用 → 运行时中止 `变量无值`（不静默给 0）。
- **糖（编译期展开，零运行期成本）**：`+= -= *= /=`（`x += e` → `x = x + e`）；`true/false` → 1/0。`++` 不做。
- for-each / 字符串表 / 持久化（跨运行）：留口二期，不做。

## §7 兼容与回滚

- 旧 app：新类型行 raw 保留（未解锁，可移动/复制/删除）；旧核心：整个操作按条拒收（不毁数据）——与 V6 家族同款，无需数据迁移。
- 回滚：功能单位=类型号，撤回构建即回旧核（盘上数据不被新核改写格式，只多出"旧核看不懂的步骤"）。
- 风险点：表达式 v2 改的是**既有**引擎——P0 必须"双端对拍 + 全量回归"先行；编译缓存失效策略（op 覆盖即重编）在 P0 单测里显式覆盖。
