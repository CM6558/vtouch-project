> 关联：`VT_SCRIPT_V1_SPEC.md`（语言）、`VTBC_V1.md`（字节码容器）。**本文件 = 存储格式唯一规范**，

> 记号：[锁] = 已锁定；[过渡] = 仅 T4..T5 迁移完成前存在；[验] = 验收判据（对齐交接单 T4.1..T4.3）。

## §1 盘上布局 [锁]

```
/data/local/vtouch-runtime/              # live（工作副本）
├── regions.conf                          # 区域表（格式不变，v2）
├── ops.conf                              # 操作表：v8（元数据行 [+ 过渡期步骤行]）
├── progs/                                # 程序旁路目录（T4 起）
│   ├── <操作名>.vts                       # 源码（可信源；编辑器写；面板不读）
│   └── <操作名>.vtbc                      # 编译产物（≤32KB；面板读 → 原样投核心）
├── current                               # 当前方案名（一行）
└── schemes/<方案名>/                      # 方案目录（同构）
    ├── regions.conf
    ├── ops.conf
    └── progs/<操作名>.{vts,vtbc}
```

- **不变量扩展**：`live == schemes/<current>` 从「两文件」扩为「两文件 + progs/ 目录」（逐字节）。

## §2 ops.conf v8 格式 [锁]

```
#vtouch-ops v8
op <名> gate <门控区域id|-> autooff <0|1> prog <哈希8hex> <大小>
step <type> <a1> <a2> <a3> <a4> <ms> <ref> <j1> <j2> <expr>      # [过渡] 步骤行，v5 原样
```

- **元数据行**（程序操作）：`op` 行 + 尾部 `prog <哈希> <大小>`。哈希 = **.vtbc 字节的 FNV-1a 32**
  （与 `VtBc.hash` 同式：`h=0x811C9DC5; h^=b; h*=0x01000193`；8 位小写 hex）。大小 = 字节数 1..32768。
  gate `-` = 无门控（同 v5 口径）；autooff 0/1。**一条元数据行 = 一个程序操作**；不含步骤。
- **过渡期**：v8 文件允许同时含步骤行（v5 十字段原样）与元数据行 —— T4..T5 迁移完成前并存；
  T5 迁移完成后写端不再产生步骤行（读端长期接受两类记录，备份还原鲁棒性）。
- **版本门**：读端接受 v1..v5（兼容读 + 翻译矩阵照旧）与 v8；其余/缺版本行 = 丢弃清空（照 regions.conf 口径）。
  **写端一律 v8**（含空表：`#vtouch-ops v8` 单行）。
- 坏记录口径照旧：单条跳过（警告）+ 不带走全表；无步骤行的步骤记录 = 坏记录；元数据行缺 `prog` 段 = 坏记录。
- 行缓冲 ≤192B（元数据行最长 ≈133B）；`pgrep`/计数口径「`op ` 开头」不变（元数据行也以 `op ` 开头）。

## §3 progs/ 规则 [锁]

- 文件名 = **操作名 + 扩展**（名字 v11 尺子：可见 UTF-8 1..15 字符、字节 ≤47、无 `/`，天然可做文件名）。
- `.vts` = 源码（可信源，编辑器编译）；`.vtbc` = 产物（≤32KB；VTBC v1 容器）。**面板只读 `.vtbc`**，
  原样投 `VT_EDIT_PUT_PROG`（不透明搬运，不解析字节）。
- **完整性校验（面板载入时）**：读 `<名>.vtbc` → 比对元数据 `<大小>` 与 FNV 哈希；不符/缺文件 → **跳过 + 告警**，
  不投核心（防坏文件以「合法字节码」形态上表跑出错误行为）。核心侧验证器（`程序非法`）仍兜底。
- 无元数据行的 progs 文件 = 不载（元数据是索引）；有元数据无文件 = 跳过 + 告警。
- 编辑器对账（T4.1）：`.vts` 与 `.vtbc` 的「源哈希」（VTBC 容器内 srcHash）与 `.vts` 现字节对账 = 编辑器侧职责。

## §4 载入 / 重放链路 [锁]

- **启动导入**：面板 `load_ops()` 读 **live**；v8：步骤行 → 步骤表（照旧）；元数据行 → 读 `live/progs/<名>.vtbc`
  → `vtouch_prog_put`（核心验证后上表）。只补缺口径照旧。
- **T8 热载**：监视集 = live 三文件（regions/ops/current）+ **live `progs/` 目录签名** + **schemes/<current>/ops.conf + progs/ 目录签名**；
  轮询 1s + 防抖 600ms → `scheme_reload()`（强制重放：scheme→live 复制 + 核心 clear + 重放）。
- **重放清空**：`vtouch_region_clear()` + `vtouch_op_clear()` + **`vtouch_prog_clear()`**（新增；清程序表）。
  重放 = `load_regions()` + `load_ops()`（读刚同步好的 live）。运行中的程序跑私有快照，清表不影响本次。
- **起跑旗标（保留）**：`ops-prog.run` 文件（内容 = 起跑名；空 = ztp1；不存在 = 不跑）——`load_ops` 收尾投一次起跑。
  验收/工具通道（T5 双跑对拍复用）；**`ops-prog-*.vtbc` 扫描（pilot 试点通道）退役**（正式链路 = 本文件）。

## §5 写入与镜像 [锁]

- **唯一创作写方 = 编辑器**（写 ops.conf v8 + progs 两件、维护 live==schemes 镜像）。
- **面板写入（兜底）**：v8 序列化 = 从核心两表忠实写出（步骤操作 → 步骤行；程序操作 → 元数据行 +
  `progs/<名>.vtbc` 从核心字节原样写回 [不透明]）。用途：未知版本丢弃改写 + 验收字节往返（见 §7）。
  面板写盘后照旧 `hr_files_note()` 自写豁免。
- **镜像同步口径（progs 目录）**：精确同步 = 拷源全量 + 删目标多余；**源目录缺失视为空**（对齐「缺失份写空合法文件」
  口径）；同步动作打日志（拷 N 删 M）。两侧方向：切换 ④ scheme→live；③ flush 与镜像 live→scheme。
- **备份 `.bak-v8`**：迁移/批量改动前 —— `ops.conf.bak-v8`、`regions.conf.bak-v8`、`progs.bak-v8/`（目录整体复制）。
  编辑器备份链提供；验收收场 = 备份还原（md5 对账）。

## §6 降级 [锁，明示]

- 旧核心/旧面板对 v8 数据 = **整份按版本门处理（丢弃）** —— 不可逆。**降级 = 用 `.bak-v8` 还原**。
- 旧编辑器 app：读 v8 保留 header 与未知尾段（`prog` 字段经 extra 保真）；不做 v8 语义 —— 「需新版应用」提示于 T5 落。
- 契约/核心零改动：程序载荷/程序表/验证器 = T3.5 已交付（v17）；本任务纯存储 + 面板 + 编辑器。

## §8 T4 子决策记录（实现口径）

1. **过渡期双格式读支持**（v5 步骤路径保留到 T5 迁移完成）：用户数据 T4 期间仍为 v5 —— 面板双分支读（v8/v5），
   风险最小；T5 迁移收尾后可评估剪除 v5 读路径。
2. **FNV-1a 32（VtBc 同式）**做产物哈希：项目内已有先例（srcHash），Java/C 双端实现十行内；比 md5 省依赖。
3. **env 门控验收钩** `VTOUCH_UI_OPS_SAVE_TEST`：面板启动导入完成后执行一次 save 往返（默认零行为；
   T3 起跑旗标同级的验收/工具通道；退役点 = T5 验收后评估）。
4. **起跑旗标保留**（§4）：扫描退役、旗标留下 —— T5 双跑对拍（t36 矩阵法）依赖它。
5. **面板操作页显示 progs**：随 T4.2 顺带（列表 + 起跑按钮；显示口径「程序 · N B」）——「正式链路可见可跑」。
